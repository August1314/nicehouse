## 总体目标
- 支持场景中多个数字人（每人独立房间活动）被统一监测、告警、可视化。
- 保持现有单数字人功能不回归，接口向后兼容。
- 为监护、健康、活动、告警链路提供按人区分的能力，并可在 UI 侧按人切换/汇总。

## 里程碑与时间（示例）
- M1（设计与基础改造，2-3 天）：数据/接口设计，PersonState 多实例化。
- M2（监护/活动/告警改造，2-3 天）：遍历多 Agent，告警携带 personId。
- M3（健康数据多实例化，2-3 天）：健康数据注册表与监测遍历。
- M4（UI 适配与体验，2-4 天）：监护/健康/热力图 UI 支持按人切换或汇总。
- M5（测试与回归，2-4 天）：自动/手动用例、性能与场景演示验证。
- M6（文档与示例，1-2 天）：开发文档、场景搭建指南、示例 Prefab。

## 阶段拆解

### 阶段 M1：设计与基础改造
- 目标：从单例 `PersonStateController` 过渡到可多实例的 `PersonStateAgent` + 管理器。
- 任务：
  1. 设计数据模型：`personId` 必填，`currentRoomId`，`state`，`stateDuration`。
  2. 拆分脚本：从 `PersonStateController` 复制为 `PersonStateAgent`，移除单例；保留 API `ChangeState(...)`、事件。
  3. 新增 `PersonStateManager`：注册/注销 Agent，提供 `GetAllAgents()`、`GetById()`，可选事件。
  4. 兼容层：保留旧单例入口（可选），但内部指向 `PersonStateManager.DefaultAgent`，用于过渡。
- 质量门控：
  - 单元/脚本测试：创建两个 Agent，注册后可查询；状态切换事件触发正确。
  - 场景 smoke：无旧代码崩溃（兼容层存在或迁移完成）。

### 阶段 M2：监护/活动/告警链路
- 目标：监护、活动追踪遍历多 Agent；告警携带 `personId`。
- 任务：
  1. `MonitoringController`：遍历 `PersonStateManager.GetAllAgents()`，对每人执行异常检测；`AlarmManager.AddAlarm(..., roomId, personId)`（为 AlarmRecord 加扩展字段或附加备注）。
  2. `ActivityTracker`：记录时附带 `personId`，统计接口支持按人/总和。
  3. 告警 UI/响应：显示 person 标签；响应逻辑可不变（灯光/音效按房间触发即可）。
- 质量门控：
  - 脚本测试：两名 Agent，分别久坐/久浴/跌倒，能各自产生告警且字段区分。
  - 回归：旧场景单 Agent 无报错，告警正常。

### 阶段 M3：健康数据多实例化
- 目标：每个数字人有独立健康数据与监测。
- 任务：
  1. 引入 `HealthDataRegistry`（或改造 `HealthDataStore`）按 `personId` 存取数据。
  2. `HealthMonitoringController`：遍历注册表/Agent，对每人检查心率/呼吸/体动；告警携带 `personId` + `roomId`。
  3. 健康数据模拟器（如有）：支持为指定 personId 写入。
- 质量门控：
  - 脚本测试：双人不同心率超阈值，分别产生命名告警。
  - 旧单人场景正常。

### 阶段 M4：UI 适配与体验
- 目标：监护/健康/热力图 UI 可按人切换或汇总。
- 任务：
  1. 监护面板：增加人物选择（下拉/Tab），显示对应状态与告警；默认“全部”显示最近告警列表。
  2. 健康面板：人物选择，展示对应生命体征；汇总视图可显示“当前选中”或“平均/最大风险”。
  3. 活动热力图：提供按人/合并开关；合并模式沿用现有效果。
  4. Control Hub Snapshot：支持显示“最高严重度的任意人”或选中人物的摘要。
- 质量门控：
  - UI 手测：切换人物无 Null/错位；告警列表 person 标签正确。
  - 旧 UI 默认选中单人或“全部”时正常工作。

### 阶段 M5：测试与回归
- 自动化/脚本用例（可用 PlayMode/Editor 工具）：
  - 注册两个 Agent，久坐/久浴/心率异常/跌倒/坠床各触发一次；验证 AlarmRecord 包含 personId、roomId。
  - 活动追踪：分别在不同房间更新，热力图合并值正确。
  - 健康：personA 心率超高、personB 正常，只触发 A 的告警。
- 手工演示检查：
  - UI 切换人物、告警标签、热力图切换模式。
  - 性能：双人监测循环耗时可忽略（< 0.5ms/帧）。

## 风险与缓解
- 兼容性风险：老代码引用单例。缓解：保留兼容层或一次性更新引用；临时提供 `PersonStateLegacyAdapter`。
- 数据同步风险：房间触发器/AI 未更新 roomId。缓解：在 Agent 入口处加 Debug 日志/警告，当 roomId 为空时提示。
- UI 复杂度：多人物切换导致绑定遗漏。缓解：统一下拉组件 + 绑定校验脚本，必要时提供模拟数据按钮。

## 验收标准
- 支持 2 人以上同时监测，告警可区分 personId + roomId。
- 单人场景无回归。
- 监护/健康 UI 可切换人物，热力图可合并/分人。
- 文档与示例齐备，新同学可按文档快速复现。
