    var record = new AlarmRecord(type, roomId);
    _records.Add(record);
    if (_records.Count > maxRecords) _records.RemoveAt(0);
    Debug.Log($"[Alarm] {type} in {roomId} at {record.time:HH:mm:ss}");
    OnAlarmAdded?.Invoke(record);
}

主要缺口与风险：
- 烟雾/燃气报警链路缺失：`SafetyDataStore` 仅生成数据未做阈值判断或触发 `AlarmType.Smoke/GasLeak`，也未与 `AlarmResponseHelper` 联动。
- 持久化/场景切换：`AlarmManager`、`SafetyDataStore` 等未 `DontDestroyOnLoad`，多场景或重载可能丢失记录。
- UI 完整度：智能监护、健康监测文档中的 UI/配置类（如监护面板、阈值 ScriptableObject）仍有待对照勾选；紧急呼叫 `AlarmType.EmergencyCall` 仅在枚举与映射中预留，未发现实际触发入口。
- 测试覆盖：目前仅有 `DataTestController` 简单调用，缺少自动化/集成测试验证烟雾、燃气、跌倒、健康异常等链路的端到端效果。
